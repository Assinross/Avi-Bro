# Сохранения прогресса - дизайн

Дата: 2026-09-30. Часть A из трёх (A - сохранения, B - облегчение сетевого трафика, C - "Проверить обновление" в меню).

## Цель

Игрок может выйти из игры и позже продолжить с того же места - один или с тем же напарником. Старые сохранения можно удалить.

## Решения (согласованы)

- Сохранение - полный слепок состояния мира, кроме монстров и мгновенных эффектов.
- Одно сохранение на "состав": `solo-<uid>` или `pair-<uidХоста>-<uidГостя>`. Хранится только последнее.
- Хранилище выбирается автоматически: с `server.py` - файлы `saves/` на ПК сервера; иначе (GitHub Pages, `?local=1`, `file://`) - `localStorage`, без вопросов игроку.
- Сохранение никогда не удаляется автоматически. После поражения можно продолжить с последнего сохранения.
- В меню нет списка для загрузки: только "Продолжить" / "Новая игра". Список всех сохранений - на отдельном экране "Сохранения", только для удаления.

## Идентификация игрока

- `uid` - случайная строка `[a-z0-9]{12}`, создаётся один раз, хранится в `localStorage['avibro-uid']`.
- Гость отправляет `uid` в `hello`: `{ t: 'hello', name, prof, uid }`.
- В `G.players[i].uid` хранится uid владельца персонажа. Хост - всегда `id 0`, гость - `id 1` (как сейчас).
- Другой браузер = другой uid = другая пара; перенос uid не делаем.

## Формат сохранения

```
{
  v: 1,                       // версия формата
  key: 'solo-abc…' | 'pair-abc…-def…',
  at: 1759250000000,          // Date.now() последней записи
  seed, diff,                 // зерно мира и сложность
  meta: { day, players: [{ n, pr, lv }] },   // "витрина" для списка
  g: { … },                   // поля G (см. ниже)
  w: { tr, bu, or, sites }    // изменения мира
}
```

**Сохраняется из `G`:** `clock, day, fireLevel, nextBoss, bossCount, nextId, stats, players` (все поля, кроме переходных `_inT`, `tx/ty`), `structs, fires, mines, drops, store, kitchen, coins, fireUp, debt, upkeepLast, crypto, merchant, wx, tstock` и прочие числовые/простые поля экономики.

**Не сохраняется:** `W`, `monsters, projs, eprojs, tele, bots, bolts, fxOut`, dirty-множества (`treeDirty, bushDirty, oreDirty`), `team` (пересчитывается), `mode`.

**Изменения мира `w`:**
- `tr` - деревья, отличающиеся от исходных (срублены / повреждены / пни / побеги, включая новые побеги с координатами) - в формате `treeRec` из `Sim.snapshot`;
- `bu` - кусты без ягод `[id, berries]`;
- `or` - повреждённая/разбитая руда `[id, hp, dead]`;
- `sites` - id открытых локаций.

Размер - десятки-сотни КБ.

**Совместимость:** при загрузке поля накладываются на свежий `Sim.create(seed)` - поля, добавленные в новых версиях, получают значения по умолчанию. Сохранение с `v` больше поддерживаемого показывается в списке как "Несовместимо" (только удаление), "Продолжить" для него не предлагается.

## Модуль `js/save.js`

Новый IIFE-модуль `AB.Save`, подключается в `index.html` между `net.js` и `main.js`.

```
AB.Save.uid()              -> string                 // свой uid (создаёт при первом вызове)
AB.Save.keySolo(), AB.Save.keyPair(hostUid, guestUid)
AB.Save.pack(G, key)       -> object                 // G -> JSON-объект сохранения
AB.Save.unpack(data, mode) -> G                      // сохранение -> новый G (Sim.create + наложение)
AB.Save.list()             -> Promise<[{ key, at, v, meta, diff }]>
AB.Save.load(key)          -> Promise<data | null>
AB.Save.write(data)        -> Promise<void>          // ошибка -> reject
AB.Save.remove(key)        -> Promise<void>
AB.Save.writeSync(data)                               // для beforeunload
```

Бэкенд выбирается по `AB.Net.server` (заполняется `Net.detect()` при старте):
- **сервер:** `GET /saves`, `GET /saves/<key>`, `POST /saves/<key>`, `DELETE /saves/<key>`; `writeSync` - `navigator.sendBeacon('/saves/<key>', json)`;
- **браузер:** `localStorage['avibro-save-<key>']` + индекс `localStorage['avibro-saves']` (массив витрин без `g`/`w`).

### Загрузка (`unpack`)

1. `AB.setDifficulty(data.diff)`; `G = Sim.create(data.seed, mode)` - свежий мир, стража в локациях.
2. Наложить `g` на `G` (поля из списка выше); игрокам восстановить `uid`, переходные поля сбросить (`left` для гостя - `true`, пока не подключится).
3. Наложить `w`: деревья (с обновлением `W.treeAt`/`W.solid` для новых побегов - как в `applySnapshot`), кусты, руду (`W.solid`), `sites[id].opened = true`.
4. Если `fireLevel > 1` - `AB.growSites(W, lv)` для каждого уровня 2..fireLevel (без спавна стражи и сообщений, т.е. не через `Sim.onFireLevel`).
5. `G.nextId` - не меньше максимального id среди сохранённых объектов + 1.
6. Имя персонажа хоста/одиночки заменяется текущим именем из поля "Ваше имя"; имя гостя - из его `hello`.

## `server.py`

- Чтение тела запроса по `Content-Length`, лимит 5 МБ (больше - `413`).
- Маршруты `/saves` (GET), `/saves/<key>` (GET/POST/DELETE). `key` - только `^(solo|pair)-[a-z0-9-]{1,64}$`, иначе `400`.
- Папка `saves/` рядом с `server.py` (создаётся при первой записи). Запись атомарно: `.part` + `os.replace`.
- `GET /saves` читает все `saves/*.json` и отдаёт витрины (`key, at, v, meta, diff`). Битый файл отдаётся как `{ key, bad: true }` - в списке "Повреждено", только удаление.
- `update_from_github` не трогает `saves/` (не входит в манифест). В `.gitignore` добавить `saves/`.

## Когда сохраняем

Сохраняет только `solo` или `host`; гость - никогда.

1. **Рассвет:** в `onDawn` ставится `G.saveReq = true`; главный цикл `main.js` видит флаг, сбрасывает его и вызывает сохранение (`pack` синхронно, `write` асинхронно).
2. **Выход в меню** (`btnQuit`, `btnMenu`) - если `!G.over` или `G.over === 'win'`.
3. **Кнопка "Сохранить" в паузе** (только solo/host) - тост "Сохранено ✓" или ошибка.
4. **Закрытие вкладки** (`beforeunload`) - `writeSync`, при тех же условиях, что п. 2. Без гарантии.

После поражения (`G.over === 'lose'`) автосохранения нет - остаётся последнее (рассвет или ручное).

Ошибка записи - сообщение в игре `Не удалось сохранить: <причина>`, игра продолжается.

## Меню

**Главное меню:** новая кнопка "Сохранения" (ghost, после "Как играть").

**Экран "Сохранения":** список из `AB.Save.list()`, новые сверху. Строка: `Avi · Охотник · День 12 · Аркада · 30.09 18:40`, для пары `Avi + Петя · День 7 · Хардкор · 29.09 21:10`. Кнопка "Удалить" - первое нажатие "Точно удалить?" (3 с), второе - удаление и обновление списка. Пусто - "Сохранений пока нет". Кнопка "Назад".

**Один игрок:** при нажатии `AB.Save.load(keySolo())`:
- есть и совместимо - экран выбора: "Продолжить" (подпись: день, профессия, сложность) и "Новая игра";
- "Продолжить" - `unpack` -> `beginGame(G, 'solo', 0)` (без выбора сложности/профессии);
- "Новая игра" или сохранения нет - текущий путь (сложность, профессия, `startSolo`). Старое сохранение заменяется при первой записи новой игры.

**Вдвоём (хост):** получив `hello` с `uid` в лобби:
- `AB.Save.load(keyPair(мойUid, uid))`; нет - текущий путь (создать мир, `init`, полный снимок);
- есть - в лобби кнопки "Продолжить" / "Новая игра"; гостю отправляется `{ t: 'wait' }`, он показывает "Хост выбирает: продолжить или новая игра…";
- "Продолжить" - `unpack(data, 'host')`, персонажу `id 1` - `left = false`, имя из `hello`; далее `init` (с `df` из сохранения) и полный снимок, как сейчас;
- гость отключился до выбора - кнопки скрываются, лобби снова ждёт.

Повторное подключение гостя во время игры - как сейчас (`p.left`), дополнительно сверяется `uid`: если он другой - новый гость в игру уже идущего мира не принимается как id 1 (сообщение "В этой игре играет другой напарник").

## Ошибки и крайние случаи

- `localStorage` недоступен/переполнен - `write` отклоняется, игроку сообщение; меню "Продолжить" просто не появляется.
- Сервер недоступен при сохранении - сообщение, игра продолжается.
- Битое сохранение (JSON не парсится) - в списке "Повреждено", только удаление.
- Гость со старой версией игры без `uid` в `hello` - считается новым напарником (`uid = 'anon'`), сохранение пары не ищется.

## Проверка

Тестов нет (по `AGENTS.md`). Ручная проверка:
1. GitHub Pages / `python3 -m http.server`: одиночная игра -> дождаться рассвета -> выйти -> "Продолжить" -> день, инвентарь, постройки, срубленные деревья на месте; монстры заново.
2. `server.py`: то же, файл появился в `saves/`; перезапуск сервера -> "Продолжить" работает.
3. `server.py`, две машины (или `?local=1`, две вкладки - браузерное хранилище): игра вдвоём -> рассвет -> выход -> снова комната -> у хоста "Продолжить" -> оба персонажа восстановлены.
4. Другой напарник -> сохранения пары нет -> новая игра.
5. Экран "Сохранения": удаление одиночного и парного.
6. Поражение -> "Продолжить" загружает последний рассвет.
7. `python3 -c "import ast; ast.parse(open('server.py').read())"`, `node --check js/save.js js/main.js js/sim.js`.
